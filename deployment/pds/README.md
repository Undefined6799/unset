# Paired PDS frontend build

`source.lock.json` fixes the official PDS image, Node builder, upstream source archive and lockfile. Its `linux/amd64` platform is the native CI target. The exact schema, Dockerfile interface and clean-checkout verifier command are in [the checker contract](../../scripts/ci/pds-ui/README.md); updating any source or package version requires reviewing that contract with this recipe.

The source is `bluesky-social/atproto` revision `5d6febdd96671891bd82f07fece7eb089c6fe931`. Its archive SHA256 is `d607296e338b066c6efb1282a8bbc05fd76009907453b20c6098c0fa739bb9be`; its `pnpm-lock.yaml` SHA256 is `b03bf840f28d91bb69a06b6252e61904611c104adc4d69e2282b2c866158cf07`. The official image's installed package tuple is `@atproto/pds@0.5.49`, `@atproto/oauth-provider@0.24.3`, `@atproto/oauth-provider-ui@0.10.7`. The builder checks these inputs before installing dependencies.

The Dockerfile builds only the UI and its supporting TypeScript projects with Node 26.12.1 and pnpm 11.11.0, using the frozen upstream lock and disabled install scripts. A scratch stage exports only the completed `dist`; the final stage replaces exactly the installed UI directory in the official image. The verifier compares the complete runtime Config and every effective filesystem entry outside that directory against the official base.

Upstream's pinned `rolldown-plugin-bundle-manifest` hashes intermediate chunks in `generateBundle`; six native manifest hashes do not match the final Vite output. After Vite succeeds, this recipe recomputes each manifest item's `sha256` from its final named file, preserves every other field and asset byte, and writes deterministic two-space JSON. The provider continues to consume its native manifest format. Source evidence: `packages/internal/rolldown-plugin-bundle-manifest/src/index.ts` and `packages/oauth/oauth-provider/src/router/assets/assets-manifest.ts` at the locked revision; see the [checker contract](../../scripts/ci/pds-ui/README.md) for the observed Vite 8.3.1 behavior.

## Theme (P2.24x)

Before the source is hashed, the recipe appends [`ui/unset-theme.css`](ui/unset-theme.css) to upstream's `packages/oauth/oauth-provider-ui/src/style.css`, so Vite bundles it into the same hashed stylesheet. It rebinds upstream's own shadcn tokens to the design sheet (fonts from the edge path `/_unset/fonts/`, colours for both schemes, 4px radius, outline buttons) and changes no component, route, form or script. Upstream's tokens are unlayered, so the theme is too, and it repeats the sheet's colours as literals; `ui/theme.test.ts` holds each one equal to `shared/ui/src/tokens.css`.

This recipe builds the first-party image `ghcr.io/undefined6799/unset/pds`. `deployment/images.lock.json` pins its digest with `origin: first-party` and `verify: cosign-keyless`, and `deployment/compose.dev.yaml` runs that ref. `deployment/compose.dev.test.ts` requires the lock entry, that compose image and a local build of this directory. `deployment/compose.local.yaml` and `deployment/compose.dev.source.yaml` build this directory's Dockerfile. On a push to `main`, `.github/workflows/publish-images.yml` builds this Dockerfile, pushes it by digest, scans it, signs it and attests it. The official `ghcr.io/bluesky-social/pds` image is only the final stage's base. Production deployment stays Alex's call (ADR 0027).
