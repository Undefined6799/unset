# PDS UI implementation plan

> For agentic workers: execute this plan slice by slice using subagent-driven-development or executing-plans.
> Accepted by Alex on 2026-10-18 (“sweet let's do it”), after requiring the backend remain the same.
> Execute through the P2.24 subdivisions in the book and ADR 0027; production/manual gates remain.

**Goal:** Match the designed PDS pages using Unset's shared UI while leaving the PDS backend unchanged.

**Architecture:** Build the exact upstream frontend with Unset presentation components. Copy only its distribution
and bundle manifest into the official pinned image. Prove that all backend files and runtime configuration remain
unchanged; preserve the native frontend's authentication and account-operation behavior.

**Tech stack:** Existing React 19.3.0, TypeScript, CSS Modules, shared UI tokens and pinned Iconoir 7.12.1; upstream
Vite, TanStack Router/Query and Lingui; existing Vitest, Playwright, Docker and Caddy tooling. No new production service.

**Spec:** [PDS UI design and boundaries](2026-10-18-pds-ui-design.md).

## Global constraints

- The backend remains the same: image filesystem changes are allowed only inside `@atproto/oauth-provider-ui/dist`; runtime image configuration remains equal to the official base.
- Login/signup and every account operation stay on `unset.ac`; no new app scopes or account-management API.
- Shared tokens and generic components live in `shared/ui`; PDS layouts are a build-only `apps/pds` package.
- Both themes and desktop/phone layouts are in scope, including Menu / Settings / Avatar on the PDS phone bar.
- Keep upstream routing, guards, hydration, sessions, requests, validation, action handlers and locale behavior.
- Preserve all four frontend entries: account, authorization, error and cookie-error.
- Custom fonts require a separately verified deployment solution; no provider source patch is allowed.
- Follow repository step IDs, ownership paths, trusted-base PR separation and source-line budgets.
- Pin exact build inputs; never patch compiled JavaScript, run postinstall rewrites or deploy an unreviewed image.

## Review focus

1. Multi-account navigation must keep every action scoped to the selected account (slices 3, 5).
2. Expired sessions/codes and rejected operations must retain native errors and safeguards (slices 5, 6).
3. Mobile keyboards, short viewports and translated labels must leave controls reachable (slices 3–6).
4. Upstream asset/CSP drift must fail verification rather than weaken policy or break sign-in silently (slices 2, 7).
5. An urgent backend upgrade must remain deployable with official UI if customization is incompatible (slice 7).

## Execution recommendation

Use small sequential slices with independent reviews at the backend-integrity, edge-security and authentication
boundaries. Execute implementation in the book’s dependency order; only independent read-only research may
proceed concurrently. Keep at most the repository-permitted three PRs waiting for Alex; do not batch the whole redesign into
one large PR. Start with slices 1–2, since their evidence determines the safe build path for all later screens.
