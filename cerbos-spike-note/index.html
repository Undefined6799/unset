### 2 and 3. Clients

PDP command, image pinned by the digest above:

```sh
docker run -d --name cerbos-tcp \
  -e CERBOS_NO_TELEMETRY=1 \
  -p 127.0.0.1:3592:3592 -p 127.0.0.1:3593:3593 \
  -v "$PWD/policies:/policies:ro" \
  -v "$PWD/config/tcp.yaml:/config/.cerbos.yaml:ro" \
  "$IMAGE" server --config=/config/.cerbos.yaml --set=telemetry.disabled=true
```

`config/tcp.yaml` sets `httpListenAddr: ":3592"`, `grpcListenAddr: ":3593"`, `adminAPI.enabled: false`, `storage.driver: disk`, `storage.disk.directory: /policies`, `telemetry.disabled: true`. The Unix container used `httpListenAddr: "unix:/socks/cerbos.http"`, `grpcListenAddr: "unix:/socks/cerbos.grpc"`, and `udsFileMode: 0o666`, with the socket directory mounted at `/socks`. Both sockets were `srw-rw-rw-` root:root. `0o666` is what let the host user connect. The image config has no user, so the process ran as root.

`GET http://127.0.0.1:3592/_cerbos/health` returned 200 `{"status":"SERVING"}`. `GET /admin/policies` returned 404 `{"code":12,"message":"Admin service is disabled by the configuration"}`.

Both logs contain `cerbos.telemetry` `Telemetry disabled` and `cerbos.otel` `Disabling OTLP traces because neither OTEL_EXPORTER_OTLP_ENDPOINT nor OTEL_EXPORTER_OTLP_TRACES_ENDPOINT is defined`. Both also log a sentence pointing at `https://go.cerbos.io/hub`. That line is a log message.

`tcpdump -i any` for 25 seconds covered the TCP container's start and the TCP decision calls. IP from the container (`172.17.0.2`) went only to `172.17.0.1`, the docker bridge, on the published ports. A second 12 second capture covered the Unix container's start and one gRPC-over-socket decision (the TCP container was also up and idle). In that window the container addresses `172.17.0.2` and `172.17.0.3` appeared only in ARP "who-has" for themselves. No DNS query from either container was in either capture.

Decisions, `bun scripts/measure.ts decisions <http|grpc> <tcp|unix>`. `checkResource` for `read` and `update`, then `isAllowed` for the named action. Principal ids are the synthetic strings `did:plc:owner` and `did:plc:other`.
